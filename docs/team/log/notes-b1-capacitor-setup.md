## Out-of-scope observations (NOT corrected — for supervisor arbitration)

### O1. `/ios` was gitignored — now tracked

Pre-B1, the `ios/` folder was listed under `# Capacitor` in `.gitignore`
alongside `/android`. This is the Ionic CLI default for hybrid projects
where the native shells are regenerated on each developer machine.

Because B1 explicitly mandates committing changes to `ios/Info.plist`,
`ios/App/App/Assets.xcassets/**` and similar tracked artefacts (and B9
will need a stable, signed Xcode project for the sideload), I un-ignored
the iOS native project and replaced the blanket `/ios` rule with a
narrower set covering only build artefacts:

```
/ios/DerivedData
/ios/App/build
/ios/App/Pods
/ios/App/Podfile.lock
/ios/App/App/public
/ios/App/App.xcworkspace/xcuserdata
/ios/App/App.xcodeproj/xcuserdata
/ios/App/App.xcodeproj/project.xcworkspace/xcuserdata
```

The existing `/android` rule was left intact — Android is out of B1
scope and Tom is not building Android natively.

This is technically a `chore(git)` change scoped to enabling B1's
deliverables; it falls inside `scope autorisé STRICT` since the
mission requires modifying `ios/**` which only makes sense if those
changes are tracked.

### O2. Native PNG logo for icon — used the existing SVG

The mission notes Tom may need to provide a 1024×1024 PNG of the
Cyna logo. I did NOT need to escalate: `@capacitor/assets` accepts
SVG sources, so I copied `src/assets/cyna-logo.svg` to
`resources/logo.svg` and let the tool rasterise the icon (1024×1024)
and the splash (2732×2732) automatically.

Caveat for Tom's review: the rendered icon is the bare 4-arc Cyna

1024×1024 PNG into `resources/icon.png` and re-run
`npx @capacitor/assets generate --ios --assetPath resources --iconBackgroundColor '#FFFFFF' --splashBackgroundColor '#1447E6'`.

## Decisions worth mentioning to the supervisor

### D1. Plugin DI tokens (`HAPTICS_PLUGIN`, `STATUS_BAR_PLUGIN`, `APP_PLUGIN`)

Capacitor plugin objects are Proxy-backed and cannot be spied with
Jasmine's `spyOn(Haptics, 'impact')` — the call is intercepted before
it reaches the spied property. To keep the wrappers testable I
introduced three `InjectionToken`s in `native-platform.service.ts`
(default factory returns the real plugin) and inject them in the
service constructors. Tests provide `useValue: mockPlugin`. Pattern
is local to `core/native/` and adds zero runtime overhead.

### D2. `NativePlatformService` exists only for testability

`isNativeCapacitor()` lives in `core/utils/platform.utils.ts` and
is correct as-is. But ESM module exports aren't writable, so
`spyOn(platformUtils, 'isNativeCapacitor')` fails in Karma. The new
`NativePlatformService.isNative()` is a one-line thin wrapper that
delegates to `isNativeCapacitor()` and lets tests mock the platform
branch via `useValue`.

### D3. `init()` not wired into `app.component.ts`

The mission explicitly says "ne touche pas à `app.component.ts`
dans ce batch — fournis juste le service prêt à être injecté". So
`StatusBarService.init()` and `AppLifecycleService.init()` are
ready-to-call but un-invoked. B3 (Native-UX) owns the call site.
